Scope: VVD strings `A2-atlas-lenses.txt` (660 keys: mapTool, atlasTool.changeGround / campaign / travel / fromImage / trade, cartographerTool).
Writer repo read (read-only): `Writers hoard desktop`, branch `main`, HEAD 8571ff3 (2026-10-21). Note: tasks/worldcraft1041-feature-inventory.md says the "current product source" is a different worktree (`D:/LocalAI/worktrees/writer-worldcraft1041`); this audit covers only the mounted `main` tree. Prior matrix rows touching this group: **A08 (Travel, marked P-U)**, **E45 (Maps pin recovery)**; all other rows below are new.

Legend: ONLINE = needs a server by nature. PRESENT / PARTIAL / ABSENT = Writer status for OFFLINE capabilities. "(inferred)" = behaviour inferred from labels only.

- Travel planner: `engines/worldgen/core/travel.ts` (`planRoute`, `travelTable`, `findStages`, `straightLineEstimates`), `engines/worldgen/components/JourneyPanel.tsx`, `journeyTypes.ts` (`WorldJourney`), `journeyOperations.ts` (`saveWorldJourney`/`deleteWorldJourney`), `journeyCreative.ts` + `components/JourneyCreativeCapture.tsx` (route -> note/scene), `useJourneyComputation.ts` + `journey.worker.ts`.

## 2. Top offline gaps worth implementing (ranked)

**1. Travel ways, pace and editable ground costs (rows 29-32, 35, 36). Size M.**
Writer already has a better physics engine than VVD's strings imply (least-time routing over biome drag, gradient, rivers, roads, seasons) but exposes none of it for editing. Refactor `BASE_KMH`, `BIOME_DRAG`, `SEASON_HOURS`, `roofKm` in `engines/worldgen/core/travel.ts` into a `TravelProfile` (ways[], groundCosts, dayHours, pace multipliers, nightBehaviour) with the current constants as built-in defaults; add `pace` to `TravelOptions` (hours/day multiplier, rest day after N hard days in `findStages`) and per-leg `modes[]` to `WorldJourney.options` (validated in `journeyOperations.validJourney`; `weldRoutes` already stitches legs). UI: a "Ways / Pace / Ground / Day" settings drawer in `JourneyPanel.tsx`, plus an hours-per-day input (currently reachable only by opening a saved journey). Persist the profile on the generated world (era-scoped like `journeys`). Risks: `journeyRecipeKey` and saved journeys must keep identical results for the default profile (add a regression test comparing `planRoute` before/after); worker serialisation (`journeyComputation.ts`) must carry the profile; `TravelMode` union is used by ruler and Map2D.

Risks: keep annotation-only (the file header says route must never be baked into carto render); performance on large worlds - animation must use `frameClock.ts`.

- Travel: stops are a single reorderable list with a mode per leg and a Directions panel that reads like a story ("Day 3 - dusk, camp at ..."). Writer: three fixed From/To/Via buttons and one global mode; strong numbers but no day-by-day narrative.
- Change ground image: VVD shows old vs new and what moves; Writer silently swaps the picture.
- Zone/text styling: VVD exposes a full inspector; Writer has colour+opacity only.
- Writer is better in: seasons, gradient/climb stats, road share, mode x season comparison table, realm crossings, paleo sea-level view, saved journeys that survive world regeneration (recipeKey warning), journey -> note/scene capture, map version history, SVG/PNG exports.
