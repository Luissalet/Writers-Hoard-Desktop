## Contract and normal use

`codecEvolution:'additive'` is optional on an Owned host block declaration. The default retains strict JSON descriptor equality. Additions preserve every old field descriptor's semantics; removal, kind/format, identity/reference-key or flag changes reject. Both stored RAW and projected view must pass the author guard; the declared initial state must validate. No automatic Source/legacy migration, new storage table, permission, tool or durable history is introduced.

The old block is not rewritten by a compatible project version selection, read, mount, cancel or portable capture. Newly added absent list/map fields appear empty in its editable view, regardless of fresh-block seeds; other new fields use declared initial values. Existing opaque values survive or cause validation failure. Reordered descriptor JSON or preview-only changes do not initiate adoption. Native reads and portable captures keep RAW and its stored codec, while the editable client exposes the view with the full RAW version token.

The first semantic edit writes data, codec and preview as one envelope. Equal/net-zero pending UI actions do not adopt or issue a UI state receipt. Equal direct save retains ordinary revision/write behavior while retaining the old stored body; direct save has no state Undo receipt. Native block/dock no-ops keep their ordinary revision, receipt and audit shape without adopting defaults. After adoption, explicit replacement/unset does not repopulate fields.

The first action evolution receipt uses the existing state runtime map and full before/after envelopes, with normal commit/abort availability. Undo compares the current logical body except revision and uses current CAS; metadata, owner, lease and release conflicts reject. It restores codec, preview, data and absence together; subsequent normal actions retain their existing inverses. A receipt changing a Tiptap atom confirms its editor draft: save the parent separately. Arbitrary composition of a UI editor port into an outer database transaction is not promised.

Compiled release availability never selects/enables a tool or creates data automatically.

## Portability and limits

History, Archive, hidden eras and readonly Source/Owned/dock projections retain their stored descriptor and data. Reader/wiki closed-DB captures, Published frozen readers, project/full JSON, Duplicate and both ZIP flows are covered by focused tests with existing visibility/reference policies. Copy/remap affects editable identities, not opaque prose or frozen reader bytes; importing does not install code.

Primary official [field](https://docs.beta.vvd.world/workshop/reference/sdk#field) and [defineDocumentCodec](https://docs.beta.vvd.world/workshop/reference/sdk#definedocumentcodec) documentation motivate the bounded added-field use case. Writer's opt-in uses its own per-envelope JSON, guard and CAS contract. Upstream `defineBlock` instead uses a host document codec and collaborative prose; the official CLI0.8.13 local scaffold was separately executed, without proving its injected host runtime, collaborative text, binary compatibility, universal migration or SDK parity. External APIs/payments are unnecessary here. Audio, assets, Notes and rich-prose limitations remain documented in their own deliveries.
