# Optional icons for local-tool menu actions

## Author contract

Use `icon?: string` on a `LocalToolMenuEntry` with `kind: 'item'`, either in the root or inside a submenu. Pass a Writer catalogue ID such as `Plus` or `MapPin`. A nonblank string is copied as supplied. An absent, blank or non-string value is omitted while the rest of a valid action remains available. Branches, labels and separators retain their existing shapes. The existing decorative submenu arrow and Back action do not become author icon fields.

In an editable mounted Source or legacy editor, the presenter uses the existing optional `client.icons` service. A catalogue match paints through `LocalToolIcon`; an unknown or unresolved ID with the service gets its neutral mark. With no icon or icon service there is no decoration. The visible label names the action; the decoration stays out of the accessibility tree. Adding an icon does not change keyboard, focus, single selection or revocation behavior.

The host and `createRecordingLocalToolContextMenu()` retain the optional leaf icon in a detached copy. The recorder returns metadata recursively but never consumes a trigger or invokes, exports or serializes callbacks. `examples.context-counter` renders `Plus` on both Increment leaves; both Reset leaves remain text-only. This adds no host for Owned/world, reader or fullscreen, no HTML or raw SVG in entries, and no new MCP command, permission, persistent menu state or callbacks in `wh_local_tool_describe`.
