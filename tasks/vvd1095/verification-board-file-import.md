# Direct Board file import — task1095 / research1487

Open Assets and choose Files, or drop local files onto the board. Images keep the existing image node, original image, title and placement flow. Audio/video goes through the normal scoped media importer, then creates the existing `entity` reference to `media/local-media`; the node stores a library ID, not another binary. Image remains an image-only picker. Gallery, copied images, existing resource Add/drag, Reference and normal library import remain available.

The picker places files around the captured viewport centre; a drop uses its captured canvas coordinates and current grid snapping, with the existing 40px batch offset. Each list is serial; overlapping Files lists preserve their valid siblings without cancelling an ordinary pending Add. Ordinary Add still retains its last-request-wins behaviour. Changing Board/era/pane, hiding or unmounting ends that batch; changing the destination layer prevents insertion there. No late result silently moves to a different layer. Errors preserve successful siblings. A file already saved in the original library remains there when its node cannot be inserted, with a readable notice when the original board remains visible. This is not atomic file-plus-node rollback.

Native players start paused. Undo/Redo and node removal affect the reference and retain the library resource. A Board-save retry uses its pending journal without importing the file again. Base/era ownership, sharing existing assets and JSON/ZIP/duplicate portability use the existing contracts.
