## Proposed bounded product contract

Project timestamps become creation-now; authored record/history timestamps and immutable artifacts keep provenance. Existing engine order/enabled IDs and appearances persist. No service/module activation follows from those fields.

Recommended saga policy for approval: a copied book remains a sibling in the same existing saga; update only that parent's children list in the commit. A copied saga gets `children:[]` rather than stealing its original books. Preserve intentional external series bindings; remap only those whose owner is the selected project. ## Storage outside Dexie — real remaining seam, not “offline unavailable”

1. Scrapper downloads/carousels/page captures live at managed userData paths `<project>/<snapshot>...`, exposed by existing list/read/deleteLibraryFile IPC. Source row paths refer to files deleted by normal source/project cleanup. A duplicate cannot keep the same mutable source paths: deleting source would break it. ZIP intentionally strips these assets. Proposed desktop-only leaf `electron/projectDuplicate/managedAssets.ts`: stage byte copies of ONLY selected snapshot-owned managed files to fresh target paths under the existing media root; return old→new path mapping + digest/size; no hard links/symlinks/network/download. Rewrite only declared paths and matching stored capture URLs; preserve arbitrary links as authored. Recheck source-file manifest before committing. Clean only this operation's uncommitted target staging on failure. Missing files produce exact diagnostics, not a successful full-asset clone. This is ordinary product duplication of synthetic/user-selected owned assets; this audit made NO file copies.
2. `publishing/fusion/project_links.py` stores project_results in `writer-project-links.db`, outside IndexedDB. Native module objects/files remain globally owned; duplicate the selected Writer project reference rows, not all library/links/paperwork/publishing stores. Current get/link tools could copy references but have no batch rollback/delete contract. A small normal native helper to list/copy/remove ONLY newly staged target bindings is needed; root owns the main/preload/runtime seam. Do not start currently disabled native modules just to inspect or duplicate links. Existing Writer engines' content is NOT all held in Dexie.
3. Interactive-fiction worlds have their own SQLite worlds/entities/relations/facts/sessions/turns/family_links, identified as native world IDs, not projectId-owned Dexie rows. Source audit finds no automatic Writer-project ownership relation proving that every native story world belongs to the selected Writer project. Preserve external family provenance refs; do not copy the entire global fiction data directory or invent a project binding. The proposal does not claim to duplicate unrelated native worlds or global native library originals.
4. Beta packages include immutable chapter HTML in DB; their optional filePath points to a generated external export. Preserve the in-DB package and regenerate/download its standalone artifact from frozen HTML when needed; do not pretend an arbitrary old output file was copied. Existing historical response package identity/idempotency must be mapped as provenance with an explicit fixture.

Dexie rows can be atomic in one RW transaction. A filesystem rename and another SQLite database are **not** atomically committed by Dexie. Minimal honest contract: stage and validate owned files/native binding refs before making target project visible; commit the Dexie project once; after-commit finalize/cleanup is explicit and retryable for that target. A publication failure may leave unreferenced staged target files, never a half-written visible project or changes to source. For native reference finalization failure, return the created project plus exact unfinished binding result/retry, not “fully duplicated” or a second target on retry. A small operation-local receipt is justified only if required for this cross-store recovery; not a new general job framework. Root must authorize this seam or approve a clearly named Dexie-only scope; the latter cannot be marketed as full managed-asset duplication.
