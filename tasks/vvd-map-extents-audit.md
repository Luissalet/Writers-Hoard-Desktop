# Map sheet extent audit and safe implementation plan

Research scope: local source inspection. Root observed VVD Map Beta Settings controls named Grow/crop sheet and width in kilometres. This audit does not assert unobserved VVD transformation behavior and creates no VVD document.

## Exact existing behavior

- `worldgen/core/types.ts` defines `WorldParams.width` as grid resolution; height is width / 2 for an equirectangular planet. `worldScale` changes procedural feature scale rather than the planet's measured circumference.
- `worldgen/recipe.ts` `commitRegeneration` replaces parameters and resets the edit list to `freshWorldEdits`. Its `rescaleRegions` preserves bookmark latitude/longitude across grid-resolution changes; this is regeneration, not a preservation-safe sheet crop/expansion.
- `worldgen/types.ts` `SavedWorldRegion` already stores a centre in world cells, `spanKm`, `params.aspect`, persistent ID/title and timestamps. `RegionSheetView` supports panning, stepped width 30–400 km, saving and PNG download. These are windows onto existing planetary terrain.
- However, `RegionSheetView` snaps every saved span to the nearest predefined width and overrides the saved aspect with its current container aspect. There are no independent edges, exact width/height fields, stable saved framing or crop/grow controls. Opening a saved region at a different viewport changes the visible north/south extent.
- The freeform sheet currently calls `requestRegion` and regenerates its own sampling lattice when span/resolution changes. `region/tiles.ts` explicitly documents the resulting differences in streams/hamlets. `region/identity.ts` gives habituation stable lattice IDs, while some detected landmarks have best-effort quantized position IDs. Preservation of all displayed local entities cannot be promised by changing the old sheet's span alone.
- Existing fixed-canon support is suitable: `tileGeometry`, `canonCover`, worker-backed cached canonical tile requests, and `composeCanonWindow` already compose exact windows with rasters, places, streams, tracks, fields, hedges and dykes. The older `requestCanonComposite`/`composeCanon` intentionally omits fields/hedges/dykes and applies output decimation; it is not a complete final-sheet compositor without adaptation.
- `worldSnapshots`, `canonTiles`, `renderedTiles` are derived caches, not authored version history. Their content identities are based on terrain parameters/edits/geography; changing only sheet framing must not invalidate the world's terrain or replay edits.
- Current Send to Maps updates the one map found by `sourceWorldId` and positions linked waypoints against the whole world. Reusing that path for a cropped sheet would misplace pins and overwrite its full-world background; it must remain separate.
- Physical distances are currently Earth-sized: camera/ruler use 40,075 km circumference, regional terrain uses 2π·6371 km, travel defaults to radius 6371 km. An arbitrary planet circumference setting is a separate metric/generation compatibility change. The new sheet width describes ground included in the frame; it does not resize the planet or silently rescale travel.

## Minimal safe implementation

1. Extend saved regions with an optional explicit fixed-frame mode/version. Existing `{x,y,spanKm,params.aspect}` already encodes the frame; no source coordinates need rewriting. Existing regions retain legacy behavior until the author chooses a new fixed sheet or converts a copy. A copy gets its own region ID and keeps the source unchanged.
2. Add a bounded frame inspector in the regional view: exact width and height in kilometres, centre, and grow/crop amounts for west/east/north/south. Compute a new centre/span/aspect; normalize longitude, handle seam crossings and clamp latitude/maximum coverage. A crop changes visible coverage only, retaining all world edits, entities, waypoints, journeys and references outside the frame. Grow reveals additional terrain from the same planet. It does not synthesize a new planet beyond its poles.
3. Fixed sheets use the shared canonical terrain/edits and exact-window compositor, with the same content identities and world-anchored geometry as the live map. Pass pristine source plus the ordered edits once. Do not supply per-sheet procedural detail/settlement settings to mutate canonical terrain; retain legacy sheet controls on legacy sheets. Preview can render existing tiles, request missing tiles asynchronously and be cancelled. Bound tile count, raster budget and worker concurrency; show actual snapped bounds if alignment changes them.
4. Make fixed framing independent of container size: fit/letterbox the saved aspect instead of replacing it with viewport aspect. Render and PNG export use the same frame, including vector layers and labels. Rendering resolution is a display choice; it cannot change canonical places or source keys.
5. Save each frame explicitly through a narrow project/world-scoped compare-and-swap region operation. Flush pending paint/region writers first. Compare the selected region's baseline, merge other current regions, preserve unrelated world metadata and keep the draft open on conflict/write failure. Save-as-copy is the default for conversion; no destructive confirmation is needed for creating a new reference window.
6. Do not call regeneration, change `WorldParams.width/worldScale`, alter the ordered edits, update waypoints or rewrite manuscript/Codex pointers. Existing caches can be reused; only newly visible canon tiles are requested. ZIP already carries `GeneratedWorld.regions`; verify the new optional mode roundtrips. Legacy project JSON does not carry generated worlds, so do not imply it exports these sheets.
7. Initial output is the existing local PNG download. If a later Send sheet to Maps is added, create a distinct standalone map/copy with frame-aware pin projection and explicit provenance, preserving the full-world map and its dated versions. Never overwrite a linked whole-world map using the existing `sourceWorldId` lookup.

## Acceptance evidence before claiming completion

- Unit geometry: asymmetric grow/crop, both dimensions, longitude seam, polar bounds, invalid/empty rectangles and budget rejection. Frame → sheet → frame is stable.
- Existing terrain: crop then expand returns the same overlapping canon samples, vector source keys and world positions. Compare cold worker, cache-hit and restored-cache output, including authored height/biome/rivers and renamed/hidden/moved local entities.
- Persistence: canonical world parameters/edits, waypoints, journeys, entity links and derived snapshot bytes remain unchanged; concurrent region saves merge independent regions and reject a stale edit to the same region. Failed saves preserve frame/title input.
- UI: exact dimensions survive reopen and 1440/720 resize; exported PNG uses those dimensions/aspect. Cancelling/closing a preview cancels its work and does not alter the source. All controls are localized and work without the network.
- ZIP roundtrip includes fixed sheet framing and original source identities. Existing map versions and full-world Send to Maps behavior remain unchanged.

This covers a real missing offline sheet-framing workflow. It does not constitute destructive raster cropping, infinite planar terrain generation or arbitrary planetary metric rescaling, which are different features and must not be presented as already equivalent.

## Implementation completed after the audit

- `SavedWorldRegion.frameMode?: 'canon'` opts into a fixed sheet. The existing automatic regional sheet remains the default, with a localized **Fix sheet · create copy** action. Conversion creates a fresh ID and leaves its source region intact.
- New `worldgen/sheets/` modules implement precise kilometre dimensions and latitude/longitude centre controls, independent positive/negative edge adjustments, bounded undo/redo, fixed aspect independent of viewport, saved-region reopening and matching PNG rendering. Fractional canonical-cell edges are cropped at render time instead of shifting coordinates or rebuilding terrain.
- Production requests share the canonical worker/cache/persistence path and exact-window compositor, including fields/hedges/dykes. Requests are limited to two concurrent tiles, sixteen total tiles and two million output cells. Cancelled work is aborted; errors offer retry. Very tall/wide PNGs use a bounded longest edge and preserve their aspect.
- Explicit save compares the selected region's baseline and world recipe. Legacy region list writes now merge only changed IDs with the same CAS helper, preserving independent concurrent sheets. Draft frame/title/unapplied edge inputs recover locally; failed saves retain the open draft. Workspace close is guarded while a frame is unpublished, and explicit close offers discard. Project deletion clears the new draft-store prefix.
- No regeneration, planet metric change, source terrain crop, outside-world generation or Send to Maps overwrite was added. World parameters, edits, waypoints, journeys, existing source pointers, map versions and terrain snapshot bytes are untouched by framing. Existing ZIP transport carries saved fixed sheets; the legacy JSON world's omission remains unchanged.

Existing `testWorldgenRecipes` five groups and `testWorldgenLifecycle` eight groups pass. Scoped ESLint and renderer typecheck pass.
