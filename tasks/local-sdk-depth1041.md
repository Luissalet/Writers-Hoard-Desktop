## Proposed smallest compatible architecture

Add src/engines/local/testing.ts and small pure leaves. Export createFakeLocalToolHost(definition,fixtures,overrides?) returning the exact LocalToolClient contract, inspectable state, recorded commands and forkClient(scope). A shared runLocalToolOperation receives an explicit transaction callback: production supplies its existing Dexie RW path; the memory host snapshots/restores its maps on failure. Queries stay read-only, with no global R transaction. callTool fakes are explicit named handlers supplied by the author; an absent operation fails rather than fabricating success. This phase is independently useful and should precede state/package changes. Generated tools receive a small author test fixture importing this public kit; existing native/Vite tests stay as integration checks.

### B. Explicit local releases and compiled-version pins (S06)

Keep the trusted-source build architecture. Do not add runtime eval, remote module imports or a binary plugin loader. Optional release metadata is {version,contentHash}; legacy modules are retained as an explicit development definition. A source package contains only the author's declared module files/assets and a pure manifest with namespace, format/API version and SHA256 file hashes. It never contains the application repo, dependencies, project data or executable installation scripts.

A normal CLI pack/check/install workflow verifies those bytes, installs an immutable release below installed/<namespace>/versions/<hash>/, and requires the normal rebuild before that release can run. Repacking byte-identical input is stable; reusing an existing hash with different bytes fails. Source package installation does not enable a project or overwrite source/data. Build-time verification derives compiled release metadata and the eager catalog; both old and new compiled releases can exist. Runtime registry resolves the version pinned for that project; component AND operation dispatch must resolve the same definition. Merely attaching a version label to the current single definition would not meet this criterion.

Project optional shared metadata: localToolInstallations[namespace] = {contentHash,revision,updatedAt}. Pins are project-wide like engine/type configuration, not era overlays; state remains Base/era. Pin changes compare expected pin revision, keep state untouched and run the target validator before use. An incompatible payload remains stored and a clear state/version error is shown; migration is an explicit author operation, not a reset. Missing compiled release keeps its pin/state and reports unavailable, never silently runs latest. No pin means the legacy development module when present; packaged tools require an explicit compiled version selection. EngineManager gains a compact release selector/status. Backup carries descriptors/pins/state but never installs code; cloning preserves immutable hashes and resets pin revisions.

S06 remains a source-package distribution contract: rebuild/relaunch is necessary for newly installed source. Runtime binary installation and remote share/publish stay explicitly outside this implementation. This is a substantive local version/pin capability without claiming the other product's loader.

### C. Common local state actions, references and Undo (S09 with an honest S02 boundary)

Optional defineLocalStateCodec descriptor declares stable field keys with scalar, map, list, prose and document/media reference kinds. It does not replace legacy initialState/validateState or change opaque old state. Descriptor/defaults are pure JSON, exported for describe/author testing and persisted as portable contracts only when used, so clone can remap declared references even if source is absent. Unknown authored strings remain byte-identical.

Proposed client additions: state.apply(actions,observedSnapshot), refs.resolve(ref), refs.open(ref), document drag encode/read helpers and a small React drop/source hook; LocalToolIcon reuses ProjectIcon. State actions identify scalar fields, map keys and stable list item IDs. Apply reads latest Project inside its existing RW transaction, three-way merges changed fields/keys and stable-ID list operations, then increments the existing namespace revision once. Disjoint edits survive; overlapping incompatible edits reject with the caller draft intact. Concurrent independent appends both land through serialized operations. No separate state database or persisted computed cache.

Prose in this first contract is normal Tiptap HTML/text with scalar CAS, NOT character-level CRDT merge/presence. A prose editor can reuse the normal formatting surface; it cannot claim collaboration or auto-merge arbitrary rich-text patches. Genuine character-level offline CRDT synchronization would require a separate dependency/persistence/migration proposal, so keep S02 marked partial rather than shipping a fake codec.

Successful state actions produce session Undo receipts with exact scope, changed paths/IDs, before/after values and observed versions. Undo uses the same action merge/CAS path and preserves remote disjoint fields; overlap refuses, transaction abort releases claims and a committed receipt consumes once. Expose ordinary Undo/Redo controls/hook to source tools and generic native state_apply/state_undo operations; do not attempt to reverse arbitrary network/filesystem effects or every built-in callTool. Existing native tool audit Undo remains its own contract.

Document refs use {kind,documentId}; current client supplies project/era. Resolve returns current title/kind/availability through effective documents; no stale stored title is authoritative. Drag payload adds source project/era for clarity, but a drop resolves in the destination client context again. Foreign project references are unavailable rather than issuing unscoped reads. The ordinary Library can provide the same thin native drag payload; source tools can also drag refs between themselves. Provide keyboard selection as an equivalent path. Native HTML5 document drops are the bounded first channel; a global pointer/touch morph engine and arbitrary extension document embeds are separate gaps, not simulated by these helpers.
