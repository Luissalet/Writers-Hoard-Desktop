## Bounded input and destination contract

1. Accept a selected folder/files, and a local ZIP using the installed JSZip dependency. Preserve nested relative paths. Detect duplicate/ambiguous paths, missing nested Notion exports and unsupported entries explicitly. Never flatten subpages by basename. No network reads or fetching attachments from original Obsidian/Notion URLs. ZIP decoding finishes outside database transactions. Existing transport/file/parser limits remain applicable and are reported; this task does not add arbitrary new budgets.
2. Supported text: Markdown/Markdown aliases, CSV and the already supported structured Codex JSON. Use the existing scalar frontmatter/printed Notion property parser, not a new YAML interpreter. Untyped Markdown defaults to a Codex custom document, compatible with the existing importer. An explicit recognized type is a suggestion with its reason shown. The user may choose a Codex category/template, a new manuscript chapter, or exclusion. No guessing from prose length, names, mentions or LLM output.
3. CSV defaults to a normal table. Show encoding/delimiter/decimal controls and a real cell preview from the existing regional CSV implementation. A file may instead become Codex records or a new timeline, after explicit column mapping. Codex rows map title/category/body plus chosen scalar properties; timeline rows map title/start/end/description/lane and optional link column. Blank/invalid mapped required values are row findings, not silent dropped records. The user must exclude or fix such rows before Apply. Column indexes are identities, so duplicate header labels do not choose a random column.
4. Initial timeline import supports exact ISO dates/ranges with the existing validator, or an explicit free-text date mode. A CSV creates its own new timeline; no append/replace of an existing timeline in this bounded release. World-calendar column inference, Excel serial dates, natural language dates, timezones and Notion database relations are not silently converted. The preview retains their original cells and offers table/exclusion instead.
5. A Markdown file creates one chapter in this mixed flow. Heading-based multi-chapter splitting and DOCX review remain the existing manuscript flow, reached by a clear action. Do not present a DOCX as an unsupported corrupt Markdown file or change its source/comment/revision plan. Reuse inspected Markdown conversion/normal writing schema, including image-only content; do not invoke native DOCX processing unnecessarily.
6. Local raster PNG/JPEG/GIF/WebP attachments referenced by selected prose are embedded as data images in the normal authored HTML, with original alt text. Use admitted image formats of the existing sanitizer/editor, not a downloaded renderer. Audio/video use `importLocalMedia` and normal media blocks, scoped to the chosen era. A missing/excluded/unsupported attachment stays visible as a specific finding with its source path; never replace it with a broken `file:` URL or a fictitious imported asset. Unreferenced assets are listed so users can explicitly import supported audio/video or exclude them. Unsupported files are explicitly excluded in the reviewed summary; no durable arbitrary-original-file archive is promised.
7. Resolve ordinary relative Markdown links and Obsidian `[[path|label]]` / `![[path]]` against the source directory and the complete selected manifest. Exact normalized paths win; extensionless/basename resolution succeeds only for one candidate. Preserve authored label/alt text. Resolve included destinations to ordinary product document links/media blocks only after the plan reserves all IDs. Excluded, ambiguous, heading/block-only or missing targets remain authored text/link plus a concrete finding, not a link to another same-named document. Existing HTTP links stay unchanged and are never fetched. CSV text cells remain literal; mapping is not formula execution.

## Plan, atomic apply, provenance and Undo

The proposed dedicated leaf service owns this workflow; it orchestrates existing domain readers and normal operations, not a generic import framework.

`inspectWorldFolderImport(scope, input, decisions?)` returns an editable plan containing per-source path/hash/format, destination/reason, title/category/template, CSV mapping/options, included/excluded rows, projected content/records, assets and resolved/unresolved links, duplicate/conflict findings, reserved destination IDs and a digest. A read has no authored database writes. Reopening or changing scope/input/options invalidates the previous generation.

`applyWorldFolderImport(scope, input, decisions, expectedDigest)` recomputes the plan outside IndexedDB, then performs one normal RW transaction. Revalidate scope, relevant effective templates/calendar/metadata, destination ID absence and every included engine using existing product checks before creating anything. No automatic engine enable. Use normal era operations/validated document store for named eras, ordinary domain operations in Base, and `addTable`/`importLocalMedia` for their own data. Do not use `saveEraDocument` as a pretend Base writer. Notify only after the outer commit. A failure in the last asset/event must roll back earlier chapters/Codex/tables and source metadata.

Proposed minimal durable metadata (root seam, to approve): `Project.worldFolderImports?: WorldFolderImportReceipt[]`, a pure leaf type with version, batch ID, optional eraId, format, source path/hash and created destination references (kind/id, plus explicit event/media child IDs where needed). It contains no source code, runtime functions, HTML cache, binary base64 or copied Project arrays. This records import identity for duplicate/conflict reporting after restart. Exact unchanged sources already imported are reported, not copied again; changed sources at that identity are conflicts and require a separate explicit new import decision, never an implicit replacement. Cloning remaps only declared IDs/scope, not opaque source paths/cell strings. Metadata validation/remap and legacy absence versus explicit empty semantics follow the existing archive seams. The exact original of a chapter can reuse manuscriptSources with a normal writing receipt; that table must not become a generic vault/ZIP attachment dump. CSV/Codex provenance does not claim an exact binary source archive.

Session Undo uses a dedicated receipt scoped to project/era with exact post-commit document versions and asset ownership. Validate every created object before any removal; any edited/deleted/externally referenced created object causes one atomic conflict rather than discarding later work. An untouched imported batch can be removed without altering pre-existing or sibling-era documents, templates, media or project settings. Receipt identity is consumed only by successful outer commit; rollback leaves it retryable. Keep Undo available after disabling an engine, consistent with existing recovery tools. Root wires ordinary global Undo only after the leaf contract exists. No generic per-object history replacement or second durable Undo system.

Portable authored data and provenance must survive normal project/full JSON, ZIP and clone. This does not install external code, mutate the original vault, preserve arbitrary Notion databases or promise re-export to the original application's complete format.
