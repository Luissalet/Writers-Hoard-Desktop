# Comparación de editores y selección para Writers

Investigación del 12-10-2026, tarea366. Base auditada: `9621fd1`, editor React/TypeScript y núcleo documental Rust propio. Se consultaron documentos oficiales y código local; **no se ejecutaron ni se midieron los productos comparados**. Las prioridades y costes son valoración de ingeniería, no resultados de una prueba de rendimiento.

La selección sirve a reportaje, ensayo, biografía y narrativa. Aplica CRITERIOS, las lecciones76/77 de `tasks/lessons.md` y el plan del hilo394: flujo individual, investigación, voz, revisión y exportación. No se propone CMS, SEO, campañas, coedición ni roles. Conservamos los motores existentes y la arquitectura híbrida; esta comparación no justifica reescribir Writers en Rust.

## Selección finita para implementar

1. Terminar354: estilos, secciones/listas y cita trazable sobre motores existentes. No dividirlo en nuevas tareas duplicadas.
2. Terminar367: revisión DOCX propia con prueba de XML y reapertura; mantener Final/Original como opciones.
3. Implementar368: ortografía española local con idioma y diccionario propio; medir corpus antes de añadir gramática.
4. Añadir **un navegador del documento derivado de encabezados**, integrado en el editor actual y MCP. No nuevo motor, tabla de contenido persistida ni otro Outline.

La selección se ha implementado en la copia aislada de Writers: estilos/secciones/listas/citas, revisión DOCX, corrector español y navegador de encabezados. La revisión y activación se registran por separado en354/367/368/408; esta matriz de documentación no acredita por sí sola una instalación. Metas, tableros, focus, historial y biblioteca ya existen. Filtros guardados, Typewriter y pares arbitrarios de snapshots son ampliaciones posteriores no seleccionadas para esta entrega. No se descargaron ni ejecutaron editores para esta comparación.

La arquitectura híbrida continúa siendo la elección útil: UI, IME, estado de capítulos y Dexie en TS; formatos/layout/documentos en Rust. Ninguna fuente aquí demuestra que una migración total mejore latencia, calidad de escritura o compatibilidad. Esa decisión necesitaría perfiles medidos, coste de reemplazar motores y corpus equivalente, no un recuento de funciones ajenas.
