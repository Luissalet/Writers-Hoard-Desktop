## Capability and data contract

A codec2 rich field can explicitly choose `paragraphs-inline/3` and declare one annotation descriptor: semantic ID, version and named scalar attributes. Attribute values match their declared string, finite number, boolean or null type and optional enum. The annotation is a complete record, rather than separately merged attributes; missing, extra or invalid values reject. The SDK `rich-annotation` action sets that record over an unchanged captured rich range; `attrs:null` removes only the annotation.

The normal collaborative editor exposes author-defined labels and value labels, Apply, Cancel and Remove. Applying unchanged values is a UI no-op. Annotation editing preserves text and the existing bold, italic, underline and link marks. The Clue notebook (`examples.inline-clues`) uses `story.clue` with `clueKey` and `state:hint|revealed`; it is a real registered Source module and document, not a separate test writer.

Existing MCP tools create/read the Source document, start convergence, capture rich ranges, apply state actions and export/import checkpoints. State Undo uses its session receipt. Captured identities retain the selected UTF-16 units; wrong enum, node/range or project/document scope cannot partially apply a preceding valid action. Two bridge keys authenticate two clients; a separately created public SDK replica supplies the independent author used by the acceptance test.

Annotations remain in saved rich data and causal checkpoints. The accepted normal project ZIP transfer preserves the Source descriptor, document identities, data and checkpoint; import/copy modes that remap identities keep their existing lineage rules. A cold process can read that persistent state while a prior process's unconsumed session Undo receipt remains unavailable. Reading or opening an older field does not automatically migrate it to the new profile.
