# Library and publishing in Writer / Biblioteca y publicación en Writer

## English

### Reading/links and paperwork by reference (04-11-2026)

Links Hoard (port 5181) and Kafka's Hoard (port 5200) are again apps of their own in the Hoard family. Writer keeps its **Reading and links** and **Documents and paperwork** modules, their switches, views, project references and every native tool name, but no longer carries engine copies: when one of these modules is ON, Writer forwards its native paths (`/links/api/...`, `/paperwork/api/...`) and tool calls to the running Hoard, found through Hoard Hub's registry (`GET :8810/api/apps`, with the family default address when the Hub does not answer). Requests and responses stream both ways (uploads, files, Range, live events); the Hoard's token is read from the file the Hub names. Kafka's Hoard journals every agent write with a reason; when a Writer caller sends none, Writer adds `Requested from Writer's Hoard (<tool>)`.

The data lives in those Hoards. On 04-11 their stores already held every record of Writer's earlier copies (links 16/16, watches 1/1, media 15/15, digests 11/11; documents 107/107, deadlines 34/34, pages 219/219) plus newer ones; Writer's old folders under `<userData>/publishing/data/{links,paperwork}` are left untouched.

When a Hoard is not running, its module answers `503 {code: "hoard_offline", start: {...}}` and the bar above the module shows the state with **Start with Hoard Hub** (Hub `POST /api/apps/<id>/start`, then waits for its health) and **Check**; when the Hoard is back the view reloads. While it runs, the bar shows its address and version and **Open Links Hoard / Open Kafka's Hoard**. Background jobs of these two functions (watches, downloads, video digests; mail, watched folders, reminders) are managed in the Hoards themselves.

REST: `GET /api/external`, `GET /api/external/{links|paperwork}`, `POST /api/external/{links|paperwork}/start`. MCP: `wh_publishing_external_hoards`, `wh_publishing_external_start {module, wait_s?}`. Overrides for tests or other installs: `WRITER_LINKS_URL`, `WRITER_LINKS_TOKEN_FILE`, `WRITER_KAFKA_URL`, `WRITER_KAFKA_TOKEN_FILE`, `WRITER_HUB_URL`. Code: `publishing/fusion/external.py`, `src/engines/publishing/ExternalHoardBar.tsx`. Tests: `tests/test_publishing_external.py` (in-memory Hoards and Hub), `npm run test:publishing` (synthetic HTTP Hoards through the real worker and MCP).

Writer incorporates the complete owned library, reading/links, paperwork/PDF and editorial publishing packages. These are Writer modules, with their original data formats and tool names. Interactive fiction remains in its existing independent worker. Cicero remains separate; Borges belongs to Writer, not Hypatia. Home/Cook and People/Dorian are separate products. No unfinished Theseus work is included.

Open **Library and publishing** in Writer. Each module starts OFF on a new profile. Enabling a module starts its owned engine on demand, over a private stdio worker and in-process ASGI dispatch. No former application server, repository or iframe is required. Background collectors, mail scanning, watches and recovery have a separate opt-in switch. Disabling the last module closes its private worker; disabling an individual module closes its native app/engine sessions. The complete editorial desktop editor opens only through its explicit command; an editor window explicitly opened by the user retains its native window lifecycle.

The library retains indexing, exact citations, collections, conversation/link sources and hybrid search. Reading retains articles, feeds, highlights, downloads, transcripts, video insight/digests and login sessions. Paperwork retains originals, OCR, PDF editing, invoices, contracts, mail, deadlines, reminders and its complete native PDF engine. Publishing retains its complete Rust engine/editor, `.gutenberg` and historical import format, styles, parent pages, stories/frames, native/raster PDF export, snapshots and process-local native undo. Existing engine limitations remain: native PDF searchability does not prove every story is searchable or establish PDF/X/PDF/UA conformance.

Library search adds an exact-terms leg to the hybrid fusion (`publishing/borges/exact_terms.py`, `Search.exact_leg`). Rare tokens of the query (identifiers with `_` `.` `-`, CamelCase, ALL-CAPS acronyms, tokens with digits, `backtick` or "quoted" text) are looked up verbatim in the chunk text inside the collection filter, scored by IDF, dropped when they occur in more than 30 % of the searched chunks (corpora under 10 chunks are not judged by that ratio), weighted 1.5 against 1.0 for BM25, and each hit reports `matched_terms`. Parameter `exact` (default true): `library_search`, `GET /library/api/search` and the **Términos exactos** checkbox in Buscar. Tests: `tests/test_borges_exact_terms.py`. The adaptation of `search.py` is recorded in `publishing/PROVENANCE.json`.

The renderer mounts the complete incorporated views in Writer's React tree with scoped styles. Module navigation is local to each surface and never overwrites Writer's hash router. File uploads preserve binary/multipart bodies; document/media responses use a chunked stdio path that preserves native Range/status/headers. Native routes retain their own semantics (for example a plain-text original is a full 200 response).

If a write has been sent but no complete native response arrives, the bridge returns `outcome_unknown` with `reconcile_action=read_current_state_before_retry`. The write may already exist: read current state before repeating it. No automatic retry occurs. Read-only failures and failures before sending retain the unavailable result. Stream cancellation travels by request ID and waits for ASGI cleanup; per-stream flow credits keep a retained download from blocking another module. OFF and worker shutdown cancel/drain their streams before closing native owners.

Concurrent consumer/OFF/EOF cancellation shares one native cancellation and protected join. An asynchronous `finally` must finish before any cancellation acknowledgement or OFF completes; repeated causes cannot interrupt its cleanup.

The existing Writer MCP bridge discovers **394 native tools**, retains their schemas, and adds module controls, federated search and two persistent project-reference tools (**401 tools** in this subsystem). UI, HTTP and MCP use the same native handlers. `wh_publishing_link_project` links a native object or output to a Writer project; `wh_publishing_project_results` lists these references. No source file is copied. The visible project selector can link the open objects and reopen saved results. The family Faustus panel retains each incorporated app's native `app_id` and `copilot-space-id`, while using Writer's tool server.

New data lives under `<Writer userData>/publishing/data/{library,links,paperwork,publishing}`. Writer's IndexedDB, renderer origin 5174, bridge tokens and fiction profile are unchanged. See `publishing/MIGRATION.json` for the real-data handoff: this change does **not** migrate or activate real profiles. Preserve SQLite WAL/SHM coherently during an idle move; never copy a running database piecemeal. Existing absolute file/asset paths must be inventoried and remapped by the migration owner without changing native IDs, tokens, history or conversation identity.

`npm run publishing:setup` installs dependencies in this worktree. `npm run publishing:bundle` builds both owned native engines and the packaged stdio worker. The reading/links engine copy (`publishing/links_native`, its Node worker and its compatibility identity) was retired on 04-11-2026: Links Hoard is the app that holds that function. Licenses and original source hashes are in `publishing/PROVENANCE.json`, `publishing/provenance/`, `publishing/native/pdf/` and `publishing/editorial/native/`. No private SDK checkout is incorporated.

Validation: `npm run test:publishing`, `publishing/.venv/Scripts/python.exe -m pytest -q tests/test_publishing_fusion.py`, renderer/Electron typechecks and the production renderer build. These fixtures use temporary stores, disable automatic jobs, use no model/GPU and do not migrate real data. They do not certify an installed release, native Rust binaries or browser interaction. Independent review, root-controlled CUA, native engine packaging/QA and real migration remain acceptance work before activation.

Kafka's Hoard anota cada escritura de un agente con un motivo; si quien llama desde Writer no lo da, Writer añade `Requested from Writer's Hoard (<herramienta>)`.

Los datos viven en esas apps. Mientras funciona, la barra muestra dirección y versión y **Abrir Links Hoard / Abrir Kafka's Hoard**. Los automatismos de estas dos funciones (vigías, descargas, digestos de vídeo; correo, carpetas vigiladas, recordatorios) se gestionan en esas apps.

REST: `GET /api/external`, `GET /api/external/{links|paperwork}`, `POST /api/external/{links|paperwork}/start`. MCP: `wh_publishing_external_hoards`, `wh_publishing_external_start {module, wait_s?}`. Variables para pruebas u otras instalaciones: `WRITER_LINKS_URL`, `WRITER_LINKS_TOKEN_FILE`, `WRITER_KAFKA_URL`, `WRITER_KAFKA_TOKEN_FILE`, `WRITER_HUB_URL`.

Writer incorpora los paquetes completos de biblioteca, lecturas/enlaces, documentos/trámites/PDF y maquetación editorial. Conserva sus formatos y herramientas nativas, además de la ficción interactiva ya incorporada. Cicero sigue separado; Borges corresponde a Writer, no a Hypatia. Home/Cook y People/Dorian siguen separados. No se incluye ni se reanuda el trabajo pendiente de Theseus.

No dependen de los antiguos repositorios o servidores. Los automatismos se activan por separado. Las vistas completas se montan en el árbol React de Writer y mantienen navegación propia, estilos acotados y el tema familiar. Las cargas conservan los bytes y los formularios multipart; los archivos se sirven por fragmentos, con las respuestas Range del motor nativo. El editor editorial completo conserva su ciclo de ventana al abrirlo expresamente.

La búsqueda de la biblioteca añade una pata de términos exactos a la fusión híbrida (`publishing/borges/exact_terms.py`, `Search.exact_leg`). Los términos raros de la consulta (identificadores con `_` `.` `-`, CamelCase, siglas en mayúsculas, tokens con cifras, texto entre acentos graves o comillas) se buscan tal cual en los fragmentos dentro del filtro de colección, se puntúan por IDF, se descartan si aparecen en más del 30 % de los fragmentos buscados (por debajo de 10 fragmentos no se aplica la proporción), pesan 1,5 frente a 1,0 de BM25 y cada acierto indica `matched_terms`. Parámetro `exact` (por defecto true) en `library_search`, `GET /library/api/search` y la casilla **Términos exactos** de Buscar. Pruebas: `tests/test_borges_exact_terms.py`. La adaptación de `search.py` consta en `publishing/PROVENANCE.json`.

El selector de proyecto permite vincular lo abierto y volver a sus objetos/resultados; las fuentes permanecen en su motor propietario. Faustus conserva las identidades nativas y los borradores de cada vista. El origen 5174, IndexedDB, tokens y perfil de ficción existentes no cambian.

Los datos nuevos quedan en `<userData de Writer>/publishing/data/{library,links,paperwork,publishing}`. El inventario de traslado está en `publishing/MIGRATION.json`. Este código no ha trasladado datos reales, copiado binarios ignorados ni activado la instalación. La raíz debe inventariar rutas absolutas, trasladar los árboles en reposo preservando IDs/tokens/historial y verificar la instalación completa. Los límites nativos del PDF siguen vigentes: detectar texto extraíble no acredita PDF/X, PDF/UA ni que todas las historias sean buscables.

Una escritura enviada sin respuesta nativa completa devuelve `outcome_unknown` y pide leer el estado antes de repetirla; no hay reintento automático. Las lecturas fallidas y los fallos anteriores al envío conservan el error de indisponibilidad. La cancelación de archivos usa el ID real y espera a que ASGI libere el recurso. Los créditos por stream permiten responder desde otro módulo; OFF y el cierre drenan sus transferencias. Regresiones: `npm run test:publishing:transport`.

Las cancelaciones concurrentes del consumidor, OFF y EOF comparten una única cancelación nativa y una espera protegida. El `finally` asíncrono termina antes de confirmar la cancelación o completar OFF; una segunda causa no puede interrumpir esa limpieza.

Preparación: `npm run publishing:setup`. Paquete completo: `npm run publishing:bundle`. Pruebas sintéticas: `npm run test:publishing` y el test Python indicado arriba. Quedan para la aceptación la revisión independiente, CUA por la raíz, la comprobación de los motores nativos empaquetados y la migración real. Un build correcto no acredita por sí solo que la interfaz arranque y funcione.


## Retryable shutdown / Cierre reintentable (931 CAS5)

A failed native shutdown keeps its app/resources and worker in error/stopping. ON and new native requests are rejected until Retry OFF actually closes that owner. Each factory exports an explicit shutdown operation with checkpoints; an exhausted lifespan/exit stack never certifies OFF. The existing native DOM remains mounted while a failed close retains its owner. The UI exposes Retry OFF and disables automatic jobs for that retained module. A different active module remains independently usable.

Library stops workers/watchers before DB; paperwork propagates client closure failures and preserves the actual SDK twin/loop until closure; reading retains its Node process; editorial sessions remain owned until joined. SDK files are unchanged. Repeated failures propagate and preserve resources. EOF retries cleanup only, without replaying native work or writes.

`node scripts/build-publishing-runtime.mjs --worker-only` reconstructs the frozen private worker from current source using existing native binaries, skipping dependency setup and both Rust builds. The normal full bundle command remains available. Synthetic source/frozen receipts and limits are in `tasks/submission931-cas5.md`; CUA, real data and installation/activation remain with root.

Un cierre nativo fallido conserva app/recursos y worker en error/stopping. ON y peticiones nativas nuevas se rechazan hasta que Reintentar cierre complete OFF de verdad. Cada fábrica conserva los pasos terminados y reintenta la operación fallida; no reutiliza un contexto agotado como prueba de cierre. La UI muestra Reintentar cierre y conserva el DOM nativo mientras se retiene su dueño. EOF reintenta sólo limpieza, sin repetir trabajos ni escrituras. El worker frozen puede reconstruirse con `--worker-only`, sin recompilar Rust ni tocar los binarios existentes.


HTTPX closure: is_closed is not proof of released resources. The owned wrapper snapshots actual default/proxy transports and HTTPcore connections before a pool can consume its list, then checkpoints each physical close. Tests cover a real SDK twin poisoned by early HTTPX CLOSED, two failing OFFs, a held third close with consumer cancellation, and an actual HTTPcore/HTTP11 pool path. SDK files remain unchanged.

CAS6 also removes each successfully closed connection from its owning pool by identity under the pool lock before advancing. Failed connections remain retained. Closing the transport afterwards therefore cannot repeat a completed connection close. The physical test counts every invocation, including a duplicate terminal close; see `tasks/submission931-cas6.md` for the corrected package and original independent witness. CAS5 evidence remains historical.
